# Local answer latency

Measure the complete request, including queueing, query embedding, retrieval, optional translation, prompt processing, generation, repair and auditing. Tokens per second alone excludes much of the waiting time. Record the model and tokenizer revision, input/output token counts, mode, cache state, hardware and competing work. Compare identical questions against an unchanged source snapshot and review the answers separately.

## Current controls

- **Fast** is the default. The compatible API value is `standard`; it does not automatically become Careful for a complex question. It makes one answer attempt and may make one bounded repair when validation fails. It reads existing citation-preview translations without generating new ones before the answer. For focused `standard` queries (excluding `careful`, `broad`, `compare`, explicit `source_page`, and attached-document flows), `app/rag_agent.py` bounds same-page neighbor expansion to the top 3 seed chunks (`fast_seed = retrieved_chunks[:3]`) while retaining trailing retrieved hits and packs prioritized context by tier (exercise answers, top-2 primary anchor `(doc_id, page_num)` pairs and same-page condition neighbors, then remaining hits) within a ~3,800-character / 5-chunk budget (keeping at least 3 chunks and unmodified `L1|` passage lines) to cut prefill latency without dropping premises.
- **Careful** uses the API value `careful` and adds an audit. An explicitly selected mode persists in the browser. The legacy `auto` API value remains available for existing clients; new UI requests use an explicit selection. Practice has its own fixed verification workflow. To avoid prefill duplication and output truncation on multi-clause answers, `build_auditor_messages` (`app/reasoning_policy.py`) omits full `sources` text when `evidence_catalog` covers >= 98% of compact source characters (< 30 entries), and `app/rag_agent.py` restricts the auditor input to cited sources while scaling `auditor_num_predict` via `min(1800, max(1000, auditor_claim_count * 160 + 400))` (capped by available context headroom).
- When numeric citation repair is needed, `format_numeric_mismatch_feedback` and `format_numeric_ban_hint` (`app/rag_evidence_validator.py`) disambiguate sibling chunks from the same page and highlight rejected digits at the end of the repair prompt (`app/rag_agent.py`) so repairs converge without inventing ungrounded values.
- In focused `standard` mode, when the top anchor page lacks digits present in the user query, `app/rag_agent.py` prioritizes a retrieved hit page covering those missing query numbers when selecting the second anchor page.
- Query embeddings use a bounded, process-local cache of 128 vectors plus a resident `NativeEmbeddingClient` (`--stream`) worker that verifies model weights via bounded stat-bound file SHA-256 caching (`get_file_sha256_cached`) and reuses verified embedding identities across requests. Vector retrieval keeps a generation- and model-bound float32 normalized matrix cache per scoped corpus (`_get_or_build_semantic_matrix`) and checks document freshness once per request scope (`freshness_request_scope`). Topic routing uses a derived sidecar index (`retrieval_tree.db`), rebuilt atomically with `scripts/build_retrieval_tree.py --replace` when stale (`inspect_retrieval_tree_health` surfaces status on `/api/health`, `/api/status`, and `scripts/dev.py check`). Answers remain uncached; strictly source-bound `practice_sessions` reuse is enabled only in verified practice bank mode (`enable_verified_bank=True` on server accounts, bypassable with `refresh=true`) after checking exact passage SHA-256 hashes, matching model/difficulty policy, `needs_review` status, and deterministic citation/choice validators, always creating a fresh session with empty answers.
- Native MLX text (`app/mlx_infer.py`, `app/trained_client.py`) and vision (`app/mlx_vision.py`, `app/native_vision.py`) run through bounded `--stream` persistent workers (`app/stream_worker.py`) under `gpu_coordinator` (`app/gpu_lock.py`). Text streaming pre-computes and deep-clones Qwen3.5 hybrid `KVCache`/`ArraysCache` prompt prefixes when the system prompt matches (capped at 2 LRU prefix entries with `mx.clear_cache()` cleanup between requests on 16 GB Apple Silicon hosts), caches compiled `response_schema` grammar processors per tokenizer across requests via `.clone()` (capped at 8 LRU entries), processes prompts in bounded prefill steps (`128` tokens by default; configurable via `MLX_PREFILL_STEP_SIZE` in `64..1024`), and constrains structured outputs (`app/rag_agent.py`, `app/reasoning_policy.py`, `app/vision_ocr.py`) with JSON `response_schema` grammar masks. On macOS startup (`app/server.py` lifespan), `TrainedModelClient.start_startup_warmup()` warms the resident `MLX_SOURCE_PROMPT` prefix once in the background under `gpu_coordinator` (automatically skipped in pytest or when `STUDY_DISABLE_STARTUP_WARMUP=1`, and cancelled cleanly on shutdown). Conflicting heavy roles (`mlx_infer` vs `mlx_vision`) evict each other cleanly via coordinator role hooks, `NativeEmbeddingClient` registers under `mlx_embedding` so peer eviction on pre-token Metal OOM retry can shed resident workers before retrying, and training jobs evict all resident workers first. Token budgeting (`app/token_counter.py`) hashes full prompts into a bounded LRU count cache.
- Generation, vision, embedding and training share the resource coordinator. Run performance measurements without a concurrent test suite or training job. The development reloader watches backend code rather than the model and data trees.

Exact token budgeting, source selection, numeric/formula checks, citation validation and failed-answer handling still apply in Fast. Removing those checks would change correctness. A shorter maximum answer can reduce latency but must not truncate the requested reasoning or conditions.

## Diagnose before changing the model

| Observation | Next check | Suitable response |
| --- | --- | --- |
| Repeated questions spend time embedding | Cold versus repeated embedding with fixed model bytes | Reuse validated query vectors |
| Retrieval is fast but the answer is slow | Prompt length, time to first token and generated tokens | Reduce irrelevant context; keep sufficient evidence |
| English sources are much slower | Optional translation calls before generation | Use cached previews in Fast; retain original evidence |
| Most requests need repairs | Raw draft, selected evidence lines and validation reason | Fix structured output and source fidelity; keep the validator |
| Careful takes several model calls | Resolved mode and generation/audit counts | Select Fast explicitly for ordinary questions |
| All applications slow down | Memory pressure, swap growth, reloader and competing jobs | Serialize model work and retain a smaller context |
| Only some documents are slow or unanswered | Extraction quality and verified vector coverage | Repair source data and index admitted text; do not fabricate vectors |

Test a complete-vector scenario in a separate database. Count vectors, validate their dimensions, finite values, normalization, source-text digest and model identity, then time lexical and semantic retrieval independently. Compare result IDs as well as speed. A small complete fixture does not establish full-corpus coverage or large-corpus performance.

On uncontended 16 GB Apple Silicon runs with warm query-embedding, semantic-matrix, and MLX KV prefix caches, retrieval/context preparation takes roughly `0.9s–8.6s` while generation accounts for `26.8s–51.3s` (`~85–95%` of `28.0s–54.4s` total single-call `standard` latency, vs `7.3s` for an out-of-corpus refusal with `0` model calls and `113.7s–233.6s` for multi-call `careful` answers taking `2–3` model calls). Reducing remaining wall time therefore depends primarily on keeping responses on a single verified call (first-attempt citation/numeric compliance), tightening answer conciseness, and evaluating further decode-stage optimizations (`speculative decoding`, adapter tuning for first-pass groundedness, or hardware/quantization tradeoffs) with separate factual and citation audits.

## Further optimizations require evidence

Persistent `--stream` model workers and cloned hybrid prefix KV caches now run behind `gpu_coordinator` with idle timeouts, explicit cancellation eviction, role-scoped mutual eviction between text and vision workers, and stat-bound model/adapter identity verification; do not add an uncoordinated background model server to reduce a benchmark number. Further gains (such as continuous speculative decoding or KV cache quantization for Qwen hybrid layers) require dedicated accuracy and citation audits before enabling.

MLX-LM documents [prompt reuse and prefill-size tradeoffs](https://github.com/ml-explore/mlx-lm#long-prompts-and-generations). Smaller prefill can reduce peak memory and may reduce throughput. Rotating or quantized KV caches need validation for the installed Qwen hybrid architecture and can affect retained context or answer quality. Backend-specific options from the [llama.cpp server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) do not configure this application's direct MLX worker.

A [LocalLLaMA benchmark discussion](https://www.reddit.com/r/LocalLLaMA/comments/1rs059a/mlx_is_not_faster_i_benchmarked_mlx_vs_llamacpp/) illustrates why prompt length, caching and warm/cold measurements matter. Its hardware, quantization and runtime differ from this deployment; community results are hypotheses to test, not acceptance evidence for this application.

Fine-tuning can improve structured answers, source selection and the rate of successful first attempts. It does not make a model with the same architecture generate each token inherently faster. Build reviewed examples covering definitions, calculations, follow-ups, missing evidence, document scope, formulas, incomplete uploads and timetable warnings. Split related documents/images across train and holdout without leakage. Keep unreviewed answers and uncertain OCR out of approved targets. Run `python scripts/audit_adapter_readiness.py --root . --strict` before any offline training run to verify corpus completion, OCR cache states, native base identity, memory/protocol preflight, dataset runtime hashes, and adapter acceptance gates read-only, and evaluate factual and citation correctness alongside latency before accepting an adapter.

All inference, embeddings, translation, OCR/vision, supervision generation and training remain local. Missing local assets produce an explicit failure rather than a cloud fallback. See [context management](context-management.md) for the request budget and memory tradeoffs.
